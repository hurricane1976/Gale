Fleet incident runbooks

Return to operations

Collector or monitor unavailable

  1. Check the collection time and source coverage on Reliability.
  2. On Gale, inspect systemctl status gale-sysmon gale-fleet-api gale-fleet-monitor.timer and their journals.
  3. Inspect Prometheus targets and node-exporter textfile errors. Missing files must remain unknown.
  4. Validate the repair using fresh API timestamps and recovered metrics; acknowledge only with an expiry.

Agent reachable but not reporting

  1. Compare listener status with reporting coverage and source last-success time.
  2. Find the owning host and confirm whether the agent is active, paused or retired.
  3. The owner checks its scheduler, wake lock, runtime exit, artifact parser and telemetry export.
  4. Repair through the host's local process. Verify a new run appears with the same identity in Metrics and Observability.

Failed or stalled task

  1. Open the run's detail and follow its lifecycle, tool and model-usage events.
  2. Distinguish quota, authentication, timeout, tool failure and malformed output; do not equate a process heartbeat with progress.
  3. Check the runtime journal and dependency before retrying. Use the same idempotency key when a control outcome is uncertain.
  4. Validate task-specific evidence, not just successful exit. Historical runs without verification stay unknown.

Backup or restore issue

  1. Check archive freshness and the last restore drill separately.
  2. On the owning host, list the archive, validate critical files and restore into an isolated temporary directory.
  3. Compare restored hashes to the manifest; record checks, archive identity and timestamps.
  4. Never restore over production as an investigation step.

Administrative control denied or uncertain

  1. Use an authorized untagged Tailscale user device. Readers cannot mutate infrastructure.
  2. Inspect the metadata audit on the Gale host; prompts, credentials and chat results are excluded.
  3. For a running/uncertain operation, inspect the target before issuing a new key. Do not retry blindly.
  4. Keep operator identity configuration in /etc/gale/operators.json; changes are an operator responsibility.
