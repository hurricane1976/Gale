How this is wired

ollama_api.py (systemd gale-ollama-api.service, 127.0.0.1:8794 behind /api/ollama/) polls the server's own API — /api/version, /api/tags, /api/ps — every 30s and rolls samples into ollama-history.jsonl (14-day retention) in the agent-owned gale-api dir, same pattern as runs-history.jsonl.

Honesty notes: this is server-side polling, not OpenTelemetry — request-level token and error counters (the SigNoz-style metrics) only exist for the caller of each request, so fleet traffic isn't itemized here; the playground's replies are, because it is a caller. Residency and VRAM come from /api/ps; the pinned qwen3.8:27b shows “pinned” because its keep-alive is -1 (re-armed every 5 min by ollama_keepalive.sh cron — an unload self-heals within one cron tick).

Admin actions act on shared infrastructure. Unload/Pull/Delete are proxied through this service with an action allowlist, model-name validation, per-IP rate limits and body caps; the no-login model is the operator's explicit choice, same as the rest of the site. Delete demands the model name be typed to confirm — it's reversible only by re-downloading.
