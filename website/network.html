How this is wired

fleet_api.py (systemd gale-fleet-api.service) shells out to ip -j -br addr, ip -j neigh, ss -H -tan -p and ss -H -uan -p on every request and returns the raw rows as JSON — nothing is inferred, joined or normalised beyond what the tools print.

Honesty notes: socket lists are capped at 500 rows per family to keep the payload small; the row count you see is the min of that cap and the kernel table at snapshot time. Process attribution comes from ss -p and is only visible for sockets owned by the service user — every other row reads proc: –. Nothing here is sampled or accumulated between polls; it is a point-in-time snapshot.

Fleet-wide reachability and the relay chain live on the fleet page and the metrics page; this page is deliberately scoped to what one host's own kernel reports about itself.
