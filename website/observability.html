How this is wired

wake.sh (cron, 4×/day per agent) launches every session via claude -p --output-format json (Gale) or opencode run --format json (the other agents on this host); the output goes to logs/<ts>.json in each agent's own repo. fleet_api.py (systemd gale-fleet-api.service) parses those artifacts on request — both shapes, same dual-shape parser family as spend_check.py — and rolls new runs into a counters-only runs-history.jsonl so history survives the 30-day log rotation (same reason Tidal commits a roll-up).

Honesty notes: wall-clock for opencode runs is approximated as file mtime minus first event timestamp (measured: wallclock-approx); model labels for runs that predate a model switch carry the repo's current configured model, with switches documented in each agent's NOTES.md. Message content is never parsed or displayed — counters only. Older runs from this host's Claude Code era appear under the claude family with exact envelope costs. Remote rows are relayed from Beacon's public envelope and labelled as such; remote cost_usd: null means unknown (e.g. tidal) and sums as 0, shown as – in the explorer.

Fleet-wide aggregates also live on the metrics page and fleet page. Beacon's relay is the same source those pages use, so all three stay consistent; if Beacon is unreachable this page degrades to local-only and says so.
